# Bugs found during CLI/TUI testing

## Bug 1: `cli_mode()` query commands always return empty

**File:** `src/main.rs` lines 124-144

**Root cause:** The `needs_connect` check is inside `if let Some(t) = task`, but query commands (`list-sessions`, `list-panes`, `list-windows`, `list-tabs`, `list-layout`) all return `None` from `cli_command_to_task()`, so they **never enter the block** and the backend is **never connected**. Without a connection, the state is empty and all query commands output `[]`.

The comment on line 125 says the opposite of what the code does:
```
// 查询类命令不需要 connect（state 为空也行）  ← WRONG
// 操作类命令需要 connect
```
But actually query commands DO need connect. Line 117 even says: "对于查询命令（list-*），需要先 connect 建立 session" — but the code ignores this.

**Fix:**
1. Move the `connect` logic OUTSIDE the `if let Some(t) = task` block
2. Connect the backend for ALL commands (both query and operation)
3. For query commands, just connect → format_output → shutdown (no task needed)
4. Remove the `needs_connect` exclusion list

```rust
// 对所有命令都 connect（查询需要 state，操作需要 session）
let needs_connect = true; // always connect
let rt = tokio::runtime::Builder::new_current_thread()
    .enable_all()
    .build()?;
rt.block_on(model.connect())?;
let _ = model.poll_events();

// 执行 task（仅操作命令）
let task = cli_command_to_task(&cmd, &model);
if let Some(t) = task {
    model.execute(t)?;
    let _ = model.poll_events();
}

// 格式化输出（对所有命令都输出）
let output = format_output(model.state(), &cmd, format);
if !output.is_empty() {
    println!("{output}");
}
```

## Bug 2: TUI pty output never displayed

**File:** `src/platform/tui/app.rs` line 81

**Root cause:** `model.poll_events()` only drains `pending_events` collected during `model.execute()`. It does NOT call `backend.take_events()` to pull fresh pty output between keyboard events. After the last keystroke (e.g., Enter after `echo hello`), the shell produces output, but no `execute()` is called, so the output sits in the pty buffer forever.

In `TerminalModel::poll_events()` (`src/core/model/terminal_model.rs` line 169):
```rust
pub fn poll_events(&mut self) -> Vec<StateChange> {
    let events: Vec<StateChange> = self.pending_events.drain(..).collect();
    // ...fires callbacks...
    events
}
```
It only drains what was already captured. Compare with `execute()`:
```rust
let outcome = self.backend.execute(&resolved)?;
let events = self.backend.take_events();  // ← this calls drain_pty_output()
self.pending_events.extend(events);
```
`take_events()` calls `drain_pty_output()` which reads from the pty.

**Fix option A (simple):** In the TUI event loop, change `poll_events()` to also pull from backend:
```rust
// Replace model.poll_events() with a method that also drains backend
let backend_events = model.backend_take_events();  // new method
model.extend_pending(backend_events);
let events = model.poll_events();
```

**Fix option B (cleaner):** Add a `refresh()` method to `TerminalModel` that calls `backend.take_events()` + extends pending + drains callbacks:
```rust
pub fn refresh(&mut self) -> Vec<StateChange> {
    let events = self.backend.take_events();
    self.pending_events.extend(events);
    self.poll_events()
}
```

**Fix option C (minimal):** In `poll_events()`, also call `backend.take_events()`:
```rust
pub fn poll_events(&mut self) -> Vec<StateChange> {
    let backend_events = self.backend.take_events();
    self.pending_events.extend(backend_events);
    let events: Vec<StateChange> = self.pending_events.drain(..).collect();
    ...
}
```

Option C is simplest but changes the semantics of `poll_events()` for all users.
Option A/B are safer. Pick based on whether other callers (GTK frontend, tests) need the new behaviour.

## Bug 3 (minor): TUI missing SplitPane keybinding

**File:** `src/platform/tui/app.rs` lines 148-183 (`key_event_to_task`)

**Missing feature:** No keybinding to split a pane in the TUI. The TUI supports:
- Alt+T: new tab (window)
- Alt+W: close window
- Alt+1..9: switch window
- Ctrl-Q/D/C: quit
- All other keys: send to shell

But there's no way to split horizontally/vertically. Need to add:
- Alt+S or Alt+X: split pane horizontally
- Alt+V or Alt+Z: split pane vertically

The backend supports `Task::SplitPane { target, dir, .. }` via LocalBackend.

Also update the status bar (`src/platform/tui/render.rs` line 197) to show the new keybinding.
