# App frontend parity inventory

Scope: `src/frontend/macos/App/`, `src/frontend/macos/main.swift`, and `src/frontend/macos/Info.plist`. Source paths below are relative to `src/frontend/macos/`; a bare Swift filename means `App/<filename>`. Counts are physical lines, including comments and test helpers. Regenerate with `wc -l src/frontend/macos/App/*.swift src/frontend/macos/{main.swift,Info.plist}`.

This is an implementation inventory, not a proposed architecture. `MainWindow.swift:1568-1595` routes the current workspace, attention, and search entry points to `UnifiedPanelController`. The older standalone controllers are listed separately. The command palette remains active (`MainWindow.swift:1458-1464`). `MainWindow+Testing.swift:1-934` adds test access, not another user-facing page. Terminal rendering, Chrome models/widgets, CoreBridge implementation, and project services outside this directory are dependencies, not independently inventoried here.

## Feasibility basis

The feasibility field gives a category followed by one reason. It describes the feature, not a promise of pixel-identical native controls. No feature in this slice has enough evidence to classify as `likely-infeasible`.

Authoritative gpui 0.2.2 API documentation was checked online at **2026-11-04T15:37:33+08:00**. References: [App](https://docs.rs/gpui/0.2.2/gpui/struct.App.html), [Window](https://docs.rs/gpui/0.2.2/gpui/struct.Window.html), [WindowOptions](https://docs.rs/gpui/0.2.2/gpui/struct.WindowOptions.html), [ClipboardItem](https://docs.rs/gpui/0.2.2/gpui/struct.ClipboardItem.html), [EntityInputHandler](https://docs.rs/gpui/0.2.2/gpui/trait.EntityInputHandler.html), [MenuItem](https://docs.rs/gpui/0.2.2/gpui/enum.MenuItem.html), and [PromptLevel](https://docs.rs/gpui/0.2.2/gpui/enum.PromptLevel.html). The local published `gpui-0.2.2` source was also inspected for font, window-kind, and accessibility APIs.

Gpui already exposes menus, clipboard text/images, native path prompts, URL opening, fullscreen/zoom, focus, text composition hooks, and raw window handles. Therefore their presence in AppKit is **not** evidence that the corresponding product feature needs a native bridge. Exact AppKit behavior not covered by those APIs is separated below.
